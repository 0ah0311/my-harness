# 허들링 앱 — 실제 작업 흐름 분석

## 작업 단계별 분석

| # | 단계 | 명사(산출물) | 멈칫 지점(게이트) | 넘어가는 지점(에이전트 경계) |
|---|---|---|---|---|
| 1 | uibowl에서 경쟁사 레퍼런스를 수집한다 | 경쟁사 레퍼런스 | 어떤 걸 수집할지 기준을 정할 때 | uibowl (외부 도구) |
| 2 | 분석하고 우리 서비스에 반영할 부분을 가져온다 | 반영 포인트 | 어떤 부분을 우리 서비스에 가져올지 결정할 때 | 없음 |
| 3 | 화면 설계 문서를 구체화한다 | 화면 설계 문서 | 화면 구조나 플로우가 불명확할 때 | 없음 |
| 4 | Figma에 UI 키스크린 2~3개를 그린다 | UI 키스크린 (390×844) | 어떤 화면을 키스크린으로 선택할지 결정할 때 | Figma (디자인 도구) |
| 5 | 내부 관계자와 협의 후 컨셉 시안을 확정한다 | 확정된 컨셉 시안 | 관계자 의견이 엇갈릴 때 | 내부 관계자 (사람) |
| 6 | 디자인 토큰·컴포넌트를 제작하고 화면 디자인에 들어간다 | 토큰, 컴포넌트, 화면 디자인 | 토큰·컴포넌트 구조를 어떻게 설계할지 결정할 때 | Figma (디자인 도구) |
| 7 | 토큰·컴포넌트가 가이드에 위반된 부분이 없는지 검토한다 | 검토 결과 | 가이드 기준이 모호할 때 | design.md (가이드 문서) |
