# 허들링 하네스 — 실제 작업 흐름

> "무엇을 위한 일인지"는 story-service.md에 있다. 이 파일은 "내가 실제로 어떻게 하는지"만 기록한다.

## 작업 단계

| 단계 | 산출물 | 게이트 (멈칫 지점) | 에이전트 경계 (넘어가는 지점) |
|---|---|---|---|
| 1. 수집 | 경쟁사 레퍼런스 | — | uibowl 도구 사용 |
| 2. 분석 | 반영 포인트 | 분석이 충분한지 확인 | — |
| 3. 설계 | 화면 설계 문서 | 설계 문서가 충분한지 확인 | — |
| 4. 키스크린 | UI 키스크린 2~3개 | 키스크린 완성도 확인 | Figma 도구로 전환 |
| 5. 협의 | 확정 컨셉 시안 | 관계자 승인 필요 | 내부 관계자(사람) 개입 |
| 6. 제작 | 토큰·컴포넌트·화면 디자인 | — | — |
| 7. 검토 | 검토 결과 | 위반 항목 = 0 확인 | — |

## 원문 작업 문장

1. 나는 uibowl에서 경쟁사 레퍼런스를 수집한다.
2. 레퍼런스를 토대로 분석하고 우리 서비스에 반영할 부분을 가져온다.
3. 분석내용을 토대로 우리 서비스 화면 설계 문서를 구체화한다.
4. figma에 레퍼런스와 화면설계서를 반영한 UI 키스크린 2~3개를 390×844 사이즈로 그린다.
5. 내부 관계자들과 협의 후 컨셉 시안을 확정한다.
6. 컨펌된 시안을 기반으로 디자인 토큰과 컴포넌트를 제작하고, 화면 디자인에 들어간다.
7. 완성된 시안에서 토큰이나 컴포넌트가 우리 가이드에 위반된 부분이 없는지 검토한다.
