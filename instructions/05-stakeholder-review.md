## 검토 안건

### 1. 기능 범위 적절성

**질문**: 5개 화면이 MVP 범위에 맞는가?

| 화면 | 포함 여부 | 검토 포인트 |
|---|---|---|
| 기록 작성 — 수영 착장 영역 | 포함 | 기존 기록 작성 폼에 섹션 추가. UI 부담 정도 |
| 착장 선택 시트 | 포함 | 바텀 시트 진입점. 내 장비 목록 표시 방식 |
| 옵션 편집 | 포함 | 전체 화면 vs 시트 확정 필요 |
| 내 장비 목록 | 포함 | 마이 페이지 진입 경로 확인 필요 |
| 기록 상세 캐릭터 카드 | 포함 | 기존 기록 상세 화면 레이아웃 변경 범위 |

**결정 필요 사항**:
- [ ] 옵션 편집: 바텀 시트 확장 vs 별도 전체 화면 중 선택
- [ ] 내 장비 목록 진입 경로: 마이 페이지에서만 접근 vs 착장 선택 시트에서도 직접 접근

---

### 2. 착장 자동 채움 동작

**질문**: 지난번 착장 자동 채움 동작에 동의하는가?

**현재 설계**:
- 기록 작성 화면 진입 시 이전 기록의 착장 값을 OutfitCard에 기본값으로 표시
- 착장을 바꾸지 않으면 추가 조작 없이 동일 착장으로 저장

**검토 포인트**:
- [ ] 첫 번째 기록(착장 이력 없음) 시 기본 착장 표시 → 적절한가?
- [ ] 자동 채움 착장이 "아직 설정 전" 상태인지 "마지막 착장" 상태인지 시각적 구분이 필요한가?

---

### 3. 옵션 편집 UX

**질문**: 탭 전환 없이 세로 스크롤 단일 화면으로 실루엣·색·무늬를 선택하는 방식에 동의하는가?

**현재 설계**:
- 슬롯 탭(수영복/수모/수경)으로 편집 대상을 전환
- 각 슬롯 내에서 실루엣 → 색(메인/포인트) → 무늬를 세로 스크롤로 한 화면에서 선택
- 목표: 새로 만들기부터 적용까지 30초 이내

**검토 포인트**:
- [ ] 세로 스크롤 단일 화면 방식이 30초 목표 달성에 적합한가?
- [ ] 수모·수경 on/off 스위치 위치(슬롯 탭 안)가 직관적인가?
- [ ] "내 장비에 저장" 토글 기본값이 off인 것이 적절한가?

---

### 4. 과거 기록 불변 원칙

**질문**: 내 장비 삭제 시 과거 기록 착장이 유지되는 것에 동의하는가?

**현재 설계**:
- 기록 저장 시 착장 값을 복사해 저장 (참조가 아닌 복사)
- 내 장비 수정·삭제 후에도 이전 기록의 캐릭터 카드는 삭제 당시 착장 그대로 유지

**검토 포인트**:
- [ ] 개발 구현 관점에서 착장 값 복사 방식이 현실적인가?
- [ ] 내 장비 삭제 팝업에서 "이전 기록에는 영향 없음" 안내 문구가 필요한가?
